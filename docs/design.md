# Design

A short summary of the design behind Autonomous-SDLC-Java. The README covers usage.

## Goal

A drop-in, gated, agentic SDLC for Java monoliths that works with whichever local agent CLI a developer already uses. The human reviews and answers yes or no; agents do the rest.

## Principles

1. **Author once, render per harness.** Content is markdown: [Agent Skills](https://agentskills.io) (`SKILL.md`) and `AGENTS.md`, both cross-harness standards. Harness-specific files are generated, never hand-edited.
2. **Deterministic first, LLM second.** Facts a parser can extract (modules, entry points, schema, dependencies) should come from code, with the LLM writing narrative on top. v0.1 asks the agent to cite `path:line`; v0.2 adds a Java analyser.
3. **Files are the state.** Every ticket is a folder in `specs/<id>/` with a `status.md` the orchestrator reads and writes. Any session or harness can resume.
4. **Enforce with tools, not prose.** Builds, tests and (from v0.3) hooks decide whether work is done, not the agent's opinion.
5. **Small context per task.** Per-module context files; agents load the index and only the modules a task touches.

## Architecture

```text
 content/  (this repo)                    your monolith
 ─────────────────────                    ───────────────────────────────
 skills/   ── install.sh ──►  .agents/skills/      ◄── Codex, Copilot, Gemini, OpenCode read natively
 roles/                       .ai-sdlc/roles/      ──► .claude/agents/ (rendered, --harness claude)
 workflows/                   .ai-sdlc/workflows/
 templates/                   .ai-sdlc/templates/
 config.yaml                  .ai-sdlc/config.yaml (yours after install)
 AGENTS.md (block)            AGENTS.md            ──► CLAUDE.md imports it
                              .ai-sdlc/context/    (generated by sdlc-context, reviewed by you)
                              specs/<id>/          (one folder per change)
```

## The orchestrator

The `ai-sdlc` skill behaves like an app inside the harness:

1. **Menu:** fix a defect, build a feature, refactor, resume a ticket, set up context.
2. **Intake:** ticket text → `specs/<id>/`, affected modules, track-fit check.
3. **Run the track:** each stage delegated to a role subagent (or run inline where the harness has no subagents), with only the inputs that stage needs.
4. **Loops without asking:** failed module builds and `must-fix` review findings go back to the implementer, up to a retry budget.
5. **Gates:** an approval card, answered `y` or `n`. A `n` takes a one-key reason and redoes the stage.
6. **Escalations:** retry budget exhausted, new cross-module dependency, new library, schema migration, protected path, high-severity finding, wrong track.
7. **Finish:** `pr.md` written, nothing committed. The human commits and opens the PR.

## Tracks

| Track | Stages | Default gates |
| --- | --- | --- |
| defect | reproduce → plan → implement → verify → review → final | plan, final |
| feature | spec → design → plan → implement → test → verify → review → security → final | spec, design, plan, final |
| refactor | characterise → plan → implement → verify → review → final | plan, final |

## Harness mapping (target, v0.3)

| Harness | Instructions | Skills | Roles → subagents | Hooks |
| --- | --- | --- | --- | --- |
| Claude Code | `CLAUDE.md` → `@AGENTS.md` | `.claude/skills/` | `.claude/agents/*.md` | `.claude/settings.json` |
| Codex CLI | `AGENTS.md` | `.agents/skills/` | `.codex/agents/*.toml` | `.codex/hooks.json` |
| Copilot CLI | `AGENTS.md` | `.agents/skills/` | `.github/agents/*.agent.md` | `.github/hooks/` |
| Gemini CLI | `GEMINI.md` → `AGENTS.md` | `.agents/skills/` | `.gemini/agents/*.md` | settings JSON |
| OpenCode | `AGENTS.md` | `.opencode/skills/` | `.opencode/agents/*.md` | TS plugin shim |

v0.1 renders Claude Code only; other harnesses use `AGENTS.md` and skills, with roles run inline.

## Roadmap

- **v0.2** Java analyser (`ai-sdlc init`): `codemap.json`, ArchUnit freeze baseline, verified/inferred context
- **v0.3** `render` for Codex/Copilot/Gemini agent formats; neutral hooks (format on edit, protected paths, verify on finish)
- **v0.4** `verify`, `doctor`, `upgrade`; demo monolith; Gradle parity
- **Later** external driver `ai-sdlc run` for parallel tickets and async approvals
